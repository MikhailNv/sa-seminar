# Системная архитектура и спецификация стека

Этот проект показывает пошаговую эволюцию IT-архитектуры сервиса отправки уведомлений.

## Структура и связь файлов

- **`состав_системы_и_взаимодействие_компонет.md`** — **описание компонентов сервиса и их взаимодействия.**
  Полный набор компонентов, их взаимосвязи, технологический стек (раздел 10), путь клиентского запроса (раздел 11) и готовность к нарезке на задачи (раздел 12).
- **`состав_системы_1_1.drawio`** — задача 1.1: состав системы.
- **`взаимодействие_компонент_1_2.drawio`** — задача 1.2: взаимосвязи компонентов.
- **`технологический_стек_1_3.drawio`** — задача 1.3: стек на схеме, обоснование — раздел 10 описания.
- **`путь_запроса_2.drawio`** — задача 2: путь точечного и batch-запроса до передачи провайдеру, сценарий с ошибкой и действия администраторов. Четыре страницы: point, batch, ошибки, слой с номерами шагов поверх схемы 1.3. Пояснения — раздел 11 описания.
- Задача 3: пригодность результата к нарезке на задачи — раздел 12 описания. Отдельной схемы нет: задача про то, как пользоваться уже сделанными схемами и описанием.

## Главный принцип эволюции

Общая нумерация задач в задании: 1.1, 1.2, 1.3, 2, 3. На текущий момент выполнены все пять.

Каждая задача:
- дообогащает главный файл `состав_системы_и_взаимодействие_компонет.md`;
- добавляет drawio-файл со схемой с названием вида `<произвольное название>_<номер_задачи>.drawio`.

Каждая последующая задача **не заменяет предыдущее, а базируется на нём и дополняет его**.
