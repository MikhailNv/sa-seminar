# Системная архитектура и спецификация стека

Этот проект показывает пошаговую эволюцию IT-архитектуры сервиса отправки уведомлений.

## Структура и связь файлов

- **`состав_системы_и_взаимодействие_компонет.md`** — **Описание компонентов сервиса и их взаимодействия.** 
  Описывает архитектуру сервиса по отправке уведомлений: полный набор компонентов, их взаимосвязи, рекомендуемые технологии и кейсы использования. Для данного общего описания сервиса добавлены два файла схем: `состав_системы_1_1.drawio` и `взаимодействие_компонент_1_2.drawio`, которые визуально отображают резульат выполнения каждой задачи.

##  Главный принцип эволюции

Общая нумерация задач в задании: 1.1, 1.2, 1.3, 2. На текущий момент выполнены 1.1 и 1.2.

Задачи 1.3 и 2 должны выполняться следующим образом:
- обязательно должно быть произведено дообогащение главного `состав_системы_и_взаимодействие_компонет.md` файла по заданию;
- обязательно должен быть добавлен drawio файл со схемой с названием вида: <произвольное название>_<номер_задачи>.drawio

Каждая последующая задача **не заменяет предыдущее, а базируется на нём и дополняет его**.
