# Архитектура SuperSurance: Краткая навигация

Этот проект показывает пошаговую эволюцию IT-архитектуры страховой компании от простого монолита к микросервисам.

## Структура и связь файлов

- **`упражнение_1.md`** — **База (Монолит).** 
  Описывает начальную архитектуру: монолитное приложение, к которому добавили API Gateway (для новых каналов продаж), Redis (для экономии на платных запросах) и Integration Layer с ACL (для безопасной изоляции внешних данных).

- **`упражнение_2.md`** — **Эволюция (Микросервисы).** 
  Прямое продолжение Упражнения 1. Из-за роста бизнеса монолит из первого файла был разделен на 5 независимых сервисов (Customer, Product, Proposal, Portfolio, Integration) с паттерном *Database per Service*.

- **`упражнение_3.md`** — **Пользовательская обработка задач.**
  Добавлены Back-office и Internal Gateway (BFF) для сотрудников, Identity Provider, Underwriting Service (очередь задач андеррайтеров, SLA, аудит), Notification Service (push-уведомления) и брокер сообщений с Transactional Outbox.

- **`упражнение_4.md`** — **Межсервисный join.**
  Query Service с витриной (CQRS read model), которая наполняется доменными событиями. Даёт сводные списки с фильтрацией, сортировкой и пагинацией без db-links.

- **`Readme.md`** (этот файл) — **Общая карта.** 
  Связывает всё воедино и задает правила развития проекта.

##  Главный принцип эволюции

Каждое последующее упражнение **не заменяет предыдущее, а базируется на нём и дополняет его**. 

Мы строим архитектуру итеративно: решения из Упражнения 1 становятся фундаментом для Упражнения 2, которое, в свою очередь, станет базой для Упражнений 3, 4, 5 и 6. Это позволяет постепенно наращивать сложность системы, сохраняя целостность и логическую связь всех компонентов от самого старта до финальной схемы.

## Главные правила

- для каждого упражнения должно быть создано 2 файла: упражнение_<number>.md - файл с подробным описанием работы и упражнение_<number>.drawio - файл со схемой упражнения из draw.io
- при добавлении новых упражнений также информация о них должна быть записа в текущий Readme.md
